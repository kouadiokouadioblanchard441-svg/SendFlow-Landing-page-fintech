name: SendFlow motion and appearance
description: The user's visual scope and motion preference for SendFlow.
---

Keep the SendFlow landing page's existing appearance unchanged unless the user explicitly asks for visual edits.

**Why:** the user said the landing page must remain as it was and objected to visual changes they had not requested.

**How to apply:** security reviews, reliability work, and backend changes must not alter the landing page's visual presentation without explicit approval.

The user explicitly asked for professional page motion across SendFlow: pages should enter and leave with polished left/right transitions.

**Why:** motion is part of the modern, professional experience they want, without requesting a redesign of the existing layouts.

**How to apply:** use subtle directional page transitions and preserve the existing visual layout unless the user separately asks to change it.

The user also wants the desktop site to feel professional while keeping the mobile presentation intact.

**Why:** desktop quality is an explicit product requirement, not a secondary consequence of mobile styling.

**How to apply:** verify public pages at desktop widths as well as phone widths; improve desktop composition without regressing mobile.

The primary mobile navigation should keep each destination in its own clearly framed card while preserving its existing links and footer actions.

**Why:** the user explicitly asked for a professional, card-framed menu.

**How to apply:** when updating the home-page mobile menu, retain distinct borders and spacing for each link card, plus the language and download actions.
